![HTML](https://img.shields.io/badge/HTML5-E34F26?style=flat&logo=html5&logoColor=white)

> **"AI가 코드를 만들어도, 최종 판단은 개발자가 한다."**

Vanilla JavaScript로 만든 일정·할 일 관리 웹앱입니다.  
프론트엔드 입문자가 **바이브 코딩(Vibe Coding)** 방식으로 AI와 함께  
기획·설계·구현·검토·개선의 전 과정을 경험하는 실습 프로젝트입니다.

---

## 1. 프로젝트 소개

이 프로젝트는 GPT·Claude·Cursor를 단계별로 활용하여  
처음부터 끝까지 대화하듯 개발하는 **바이브 코딩 방식**을 경험하는 실습입니다.

- 코드를 바로 작성하는 대신, **기획 → 설계 → 구현 → 검토 → 개선** 순서로 진행
- AI가 생성한 코드를 그대로 쓰지 않고, 직접 읽고 이해한 뒤 수정 요청
- Samsung One UI 디자인 가이드라인을 참고해 모바일 친화적 UI 구현
- 새로고침해도 데이터가 유지되도록 `localStorage` 연동까지 완성

```
vibe_myTodo-app-ui/
├── index.html   # 화면 뼈대 (통계, 목록, 하단 고정 입력창, 푸터)
├── style.css    # 디자인 토큰, 테마, 단일 열 레이아웃
├── script.js    # 모든 앱 동작 (CRUD + localStorage + 드래그 + DOM 흐름 패널)
├── prompt.md    # AI와 주고받은 주요 프롬프트 기록
└── README.md    # 프로젝트 문서 (현재 파일)
```

## 5. 주요 기능

### ✏️ Todo 추가
- 하단 고정 입력창에 텍스트를 입력하고 **`+` 버튼** 클릭 또는 **Enter** 키 입력
- 빈 값(공백)은 추가되지 않음

### ☑️ 완료 토글
- 체크박스 클릭 시 완료 ↔ 미완료 상태 전환
- 상태 변경 시 통계·필터가 함께 업데이트됨

### 🗑️ Todo 삭제 / 완료 비우기
- 각 항목 우측의 **삭제 버튼**으로 개별 항목 제거
- **완료 비우기** 버튼으로 완료 항목 일괄 삭제

### ✏️ 제목 인라인 편집
- 제목을 **더블클릭**하면 편집 모드로 전환
- Enter로 저장, Esc로 취소

### 🔍 필터
- 전체 / 진행 중 / 완료 항목만 골라서 볼 수 있음

### 🗓️ 마감일
- 달력 아이콘을 눌러 마감 날짜·시간 선택(선택사항)
- 임박(24시간 이내)·지남 상태를 색상으로 표시
- 마감일이 빠른 순서로 자동 정렬

### 🔢 드래그 앤 드롭
- 마감일이 없는 항목을 마우스로 드래그해 순서 변경
- 변경된 순서는 `localStorage`에 저장되어 새로고침 후에도 유지

### 📊 통계
- 상단에 전체·완료·진행 중 개수를 3열로 실시간 표시

### 🌙 테마
- 라이트/다크 모드 전환, 선택한 테마는 `localStorage`에 저장

### 💾 데이터 저장
- 모든 변경사항이 `localStorage`에 자동 저장
- 페이지를 새로고침해도 목록이 그대로 복원

### 🛡️ XSS 방지
- 사용자 입력을 `textContent`로 삽입해 HTML 주입 차단

### 🖥️ DOM 흐름 패널 (학습용)
- 우측 하단 **DOM 흐름** 버튼으로 열고, 조작 시 내부 처리 흐름을 실시간 확인

## 6. 사용한 프롬프트 기록

AI와 총 **5단계의 주요 대화**를 통해 완성했습니다.

### 1단계 — 초기 기능 구현
> "바이브코딩 입문자를 위해 자바스크립트를 이용해서 웹앱에 일정관리를 위한 전형적인 필수 기능을 구현해줘"

### 2단계 — UI 레이아웃 전면 개편
> "통계 패널 상단 이동 / 입력창 하단 고정(메신저형) / 단일 열 통일 / 기존 기능 유지 + CSS 토큰 재사용 + 변경 이유 주석"

### 3단계 — 리팩터링 + 디버깅
> "`var` → `const`/`let` 교체 / DOM 직렬화 구조 → JS 배열 상태 관리로 변경 / 중복 코드 함수화 / 기존 기능 유지 / 변경 부분마다 주석 작성"

### 4단계 — DOM 흐름 시각화 패널
> "사용자 조작 시 이벤트→함수→DOM→화면 흐름을 우측 하단 반투명 패널에 실시간 표시 / 최근 5건 유지 / 열기·닫기 토글"

### 5단계 — 드래그 앤 드롭
> "HTML5 기본 API만 사용 / 마감일 없는 항목만 수동 재정렬 / 순서를 localStorage에 저장 / 마감일 자동 정렬과 충돌 없이 처리"

> 📄 전체 프롬프트 상세 내용은 [prompt.md](./prompt.md) 참고

## 7. AI 생성 결과 검토 기준

AI가 코드를 생성한 후, 아래 기준으로 직접 검토했습니다.

| 검토 항목 | 확인 내용 |
|-----------|-----------|
| **가독성** | 변수명과 함수명만 봐도 역할이 바로 이해되는가? |
| **함수 크기** | 하나의 함수가 하나의 역할만 하는가? |
| **데이터 흐름** | 데이터 변경 → 저장 → 화면 업데이트 순서가 일관되는가? |
| **예외 처리** | 빈 입력, 없는 데이터 등 엣지 케이스를 처리하는가? |
| **보안** | 사용자 입력을 그대로 HTML에 넣지 않는가? (XSS 방지) |
| **주석** | 초보자가 읽어도 이해할 수 있는 주석이 있는가? |

> 💡 **AI가 코드를 만들어도, 최종 판단은 개발자가 한다.**  
> AI가 생성한 코드가 완벽해 보여도 반드시 직접 읽고 이해해야 합니다.  
> 이해하지 못한 코드는 내 코드가 아닙니다.

## 8. 수정 요청 내용

초기 AI 생성 코드에서 다음 사항을 직접 검토하고 수정 요청했습니다.

### DOM 직렬화 구조 → 배열 상태 관리로 전환

| 기존 방식 | 변경 후 | 이유 |
|-----------|---------|------|
| DOM에서 직접 데이터를 읽는 구조 (`serializeFromDom`) | `todos` 배열을 단일 상태(SSOT)로 관리 | DOM과 데이터가 어긋나는 버그 방지 |

### 함수 최소 단위 분리

기존에 뭉쳐 있던 로직을 역할별로 분리했습니다.

```
renderTodos()    →  renderFullList() + applyFilterClassToRows() + paintChrome()
handleSubmit()   →  handleComposerSubmit() + dueInputToIso() + nextNoDueOrder()
통계 계산        →  computeStats() + paintStats()
```

### localStorage 연동 강화

- `loadTodosFromStorage()` — 페이지 로드 시 저장된 데이터를 안전하게 복원 (`try/catch` 포함)
- `persistTodos()` — 데이터 변경 시마다 자동 저장, 용량 초과 예외 처리

## 9. 배운 점

1. **기획 문서가 곧 개발의 지도다** — 기술명세서(기능·화면·데이터 구조)를 먼저 작성하고 나니, Cursor에 내릴 지시가 훨씬 구체적이고 결과물도 예측 가능해졌다.

2. **프롬프트에 제약 조건이 필수다** — "기존 기능 유지", "파일 3개 분리" 같은 제약을 명시하지 않으면 AI가 과잉 생산하거나 구조를 임의로 바꾼다는 것을 직접 경험했다.

3. **AI를 개발창과 평가창으로 분리해 쓰면 효과적이다** — Cursor로 구현하고, Claude로 검토하는 역할 분리 방식이 코드 품질을 높이는 데 실질적으로 도움이 됐다.

4. **localStorage는 문자열만 저장한다** — 배열과 객체는 `JSON.stringify()`로 변환해서 저장하고, 꺼낼 때는 `JSON.parse()`로 복원해야 한다. 저장 실패도 `try/catch`로 방어해야 한다.

5. **AI를 사용하는 법도 실력이다** — 좋은 프롬프트를 쓸수록 좋은 코드가 나온다. "더 명확하게", "더 작게 분리해서", "이유를 주석으로 달아줘" 같은 구체적인 요청이 AI를 잘 활용하는 핵심이다.
